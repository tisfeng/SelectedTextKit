# 回复规范

## 语言

- 除非用户明确要求其他语言，否则使用简体中文沟通。
- 新建或修改的仓库治理文档、计划、历史、参考资料、skill 和 Agent 配置使用中文；代码注释使用英文。
- 标识符、API 名称、命令、路径、固定输出契约和品牌名称保留原文。
- 不因为引用或附件使用其他语言而改变回复语言。

## 结果顺序

先给实际结果，再提供验证所需的最少证据：

1. 完成、未完成或受阻状态；
2. 核心变更路径和行为；
3. 实际运行的检查、失败及未运行检查；
4. commit、push 或外部交付状态；
5. 只有需要用户决定时才提出一个简短问题。

不要把方案写成完成结果，也不要把静态检查写成 build 或 runtime test。篇幅与任务复杂度匹配。

## 交付表达

- 标题、commit message 和 PR 描述优先表达正向行为。
- 除非用于说明兼容性或安全边界，不在主要结果中展开被排除方案或附件无关内容。
- 复杂任务报告准确最终 Git 状态和未验证范围。
- 显式调用 commit、review、PR 或 release 工作流时，遵循其固定输出契约。
