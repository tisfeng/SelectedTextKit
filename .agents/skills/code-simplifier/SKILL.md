# 代码简化

在不改变可观察行为的前提下，提升代码清晰度、一致性和可维护性。

## 核心规则

- 修改前理解变更代码、调用方、测试、配置和数据格式。
- 保留 public API、输出、错误行为、状态转换、并发边界、序列化格式和用户可见行为。
- 除非用户指定更大范围，只关注近期变更或用户明确指出的范围。
- 减少不必要的嵌套、重复、间接层和过度压缩的表达式。
- 优先使用明确名称和控制流，不以减少行数为目标。
- 保留能够表达领域概念或隔离副作用的有效抽象。
- 删除只重复代码的注释，保留解释意图、兼容性、并发和恢复约束的注释。
- Planning 或 review 请求只输出建议；只有 implementation 获得授权后才修改文件。

## 工作流程

1. 确定准确变更范围和行为契约。
2. 检查相关调用方、测试、配置和平台条件。
3. 选择最小的行为保持型简化。
4. 应用仓库和语言专项约定。
5. 运行变更行为所需的验证。
6. 报告变更路径、保留行为和未运行检查。

处理 Swift、SwiftUI、AppKit 或 Xcode 时，还要读取 [`references/swift-xcode.md`](references/swift-xcode.md)。
